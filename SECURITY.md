# Security reporting

Do not post passwords, tokens, personal data or exploit details in public issues. If GitHub private vulnerability reporting is enabled for this repository, use its Security tab to report privately. Otherwise obtain a private reporting channel from the maintainer before sharing sensitive details. No monitored email address or response-time commitment is currently established.

Include the affected revision, minimal reproduction, expected/actual behavior and impact. Use synthetic accounts and disposable databases; do not test against systems without authorization.

This starter has no published supported-release matrix. Dependency auditing and regression checks reduce known risks but do not certify a deployment. Before external release, maintainers must establish a monitored reporting channel, ownership and a supported-version policy. Deployment limitations are recorded in docs/release-readiness.md.
